### 2026-11-15 時間・デート場所・トークに集中するモード・交際中の早送り（指示）

- 操作ごとのゲーム内時間：いいね（いいね返しも）30分、トークは1送信20分（丁寧な返信も同じ）。プロフィールを開く2分・スキップ30秒はそのまま。
- 「男の容姿4を20枚増やす」は調べた結果（1プレイで出てくる容姿4の男性は5〜8人、素材136枚は余っている）を受けて、指示で取りやめた。
- 男性のデート場所選び（女性の化粧と対になる手間）：デートの日の1時間前に「お互いの最寄り駅を確認する」→「中間あたりの駅を確認する」（お互いの居住地の真ん中に近い地域）→「お店を確認する」（店の種類はデートの種類から）の3回。最後に「今日は◯◯の△△にしようと思います！」と相手に送る（`date_venue`）。
- トークに集中するモード（`focusMode`）：いいね・マッチの通知を出さない（いいねはたまっていく）。アプリを閉じると、仕事・睡眠・プライベートの出来事は飛ばし、メッセージか確認が必要な場面（デートなど）が来るまで自動で早送り。返事を待つ相手もデートの予定もないときは早送りを止めて知らせる。入り方：やり取り中の相手がいるとき「アプリを閉じる」を押すと「トークに集中して閉じる／ふつうに閉じる」を選ぶ画面、ロック画面の「💬 トークに集中する」、マイページの通知の欄。集中モード中は画面上部とロック画面に表示し、そこからやめられる。
- 指示：トークに集中するモードは、3人以上とマッチしてから使える（それまではロック画面・マイページ・閉じ方の選択に出さない。`focusUnlocked`。いったん「いいね10件」にしたが、同じ日の指示でマッチ3人に変えた）。
- 指示：集中モード・交際中も時間は自動で進む。早送りが止まった後（メッセージが届いた・待つ相手がいない）は、ロック画面の時計がふつうの速さ（約13秒で1日）で進み、睡眠・勤務などは今までどおり表示のあと飛ばす。もう一度アプリを閉じると、また早送りから始まる。
- 指示：もらったいいねも、さがすと同じくスワイプで選べる（右でマッチ＝いいね返し、左で見送る、タップでプロフィール）。「フリック／一覧」で切り替え、選んだ方を端末に覚える（初期はフリック）。残りが少なくなったら続きを読み込む。

## 技術構成

- React 19＋TypeScript（7.0）＋Vite 8。テストは Vitest 5、自動プレイ集計は tsx。既存実装はなかったため新規作成。
- ゲーム本体はAPIを一切呼ばない。完成済み画像（`public/portraits/`）とマニフェスト、ゲームデータだけで動く。`vite.config.ts` の `envPrefix` は `VITE_` のみで、`GEMINI_*` はブラウザ側に露出しない。
- 状態はエンジンが一括で持ち、UIは `dispatch(state, action)` で新しい状態を受け取る。乱数（sfc32）の状態を保存データに含めるため、同じシードと操作列で同じ結果になり、再読込で再抽選されない。
- 相手NPCの属性は「シード＋連番」から決定的に生成する。受信いいねは件数だけを数え、確認した分だけプロフィールを作る（数百件の確認操作を強制しない）。
- 1日を「開始（出来事）」と「締め（週末・月末の精算と勝敗判定）」に分け、選択が必要な場面はその日の締めの前に解決する。これで「同日にライフ0なら失敗を優先」を保証する。
- Gemini は 2026-10-18 時点の公式資料が Interactions API（`POST /v1beta/interactions`）で記述されていたため、生成・レビューとも同じ形式のREST呼び出しに統一した（SDKの異なる世代のサンプルは混ぜていない）。

## 仕様の数値についての提案（変更していません）

1. **（2026-11-03に対応：停滞を新設）送信を控えると男性の消耗がほとんどなくなる**：週−8は「反応待ちの終わった送信が20件以上」で発生するため、週に数件だけ送る方針では探索中の消耗が月−2（＋12か月後に月−3）だけになる。自動プレイでは、M07の「送信を絞る方針」は日数中央値287日（約41週）でクリア率63%だった。実際の人間は数十週の操作に耐えにくいが、ゲームとしては「待てば報われやすい」状態。**案**：送信数にかかわらず「30日間マッチ・会話の進展が0なら月末−3」などの停滞ダメージを追加する。
2. **M10の初期希望（25〜32歳・容姿4以上）**では自動プレイのクリア率が0%（候補の大半が相手側の希望年齢外）。仕様どおり「条件を変えないと厳しい」体験になっているが、初期希望のままの勝ち筋は実質ない（条件を広げる・絞った送信では15〜53%）。選択画面の「自分の判断が効くところ」に仕様§11の「年齢・容姿条件の一部を変える」を表示している。**案**：初期希望のままでも、相手側の希望年齢に幅のある候補を少数混ぜるかを仕様で決める。

## 画像まわりの判断

- 生成は `gemini-3-pro-image`（Nano Banana Pro、モデル一覧で安定版を確認）、レビューは `gemini-3.8-flash`（構造化出力の公式例のモデル）。環境変数で切り替え可能。
- 解像度は1K（928×1152相当）・縦4:5。プロフィール表示に十分で、料金は2Kと同じ（$0.134/枚）。4Kや別サイズは作っていない。
- 生成画像は受け取ったバイト列をそのまま保存（JPEG）。再圧縮しないことで来歴情報（SynthID等）を保つ。
- 画像ファイルの有無（台帳・マニフェスト）と、プロフィールで顔を公開しているか（`photoVisible`／NPCの `profilePhotoVisible`）は別の状態として扱う。NPCは `portraitAssetStatus: 'not_created'` で、写真公開済みなら「写真あり・外見3/5」と文字で示す。共通アイコンは外見の値で色や形を変えない。
